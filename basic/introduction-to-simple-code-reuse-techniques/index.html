简单的代码复用技术简介

代码复用

Section titled “代码复用”

前面我们介绍了编程语言，现在我们再来谈谈代码层面的问题——代码复用。

当编写程序时，如果同一个功能需要被多次使用，而我们每次都复制相同的代码，一方面会导致代码量迅速膨胀，另一方面在后续修改时也更容易出现遗漏或错误。

一个功能被使用了 3 次，假设每次修改出错的概率为 10%，那么需要修改 3 处代码时，至少出现一次错误的概率可以近似表示为： 1−(1−10%)3≈0.2711 - (1 - 10\%)^3 \approx 0.2711−(1−10%)3≈0.271，（这里假设每次修改出错相互独立，仅用于说明趋势，实际情况可能更复杂）。而如果我们通过代码复用，将该功能集中在一个地方实现，只需要修改一次，那么出错概率就是 0.1，大大降低了风险。

“代码复用”指的是通过函数、类、模块等方式，将重复的逻辑 抽象 出来，从而在多个地方复用同一份代码。

Note

抽象（Abstraction）：从具体事物中提取出共性特征，忽略不重要的细节，从而形成更通用表示的过程。

代码复用（Code Reuse）：代码复用是指将已有的代码通过抽象与封装，在多个地方或多个项目中重复使用，从而避免重复开发的一种软件设计方法。

理想情况下，每一项功能只编写一次，避免重复代码。这一原则被称为 “一次且仅一次”（Once and Only Once），也与 “Don’t Repeat Yourself”（不要重复你自己，简称 DRY）原则一致。

Note

一次且仅一次（Once and Only Once）：一次且仅一次是指在代码中，每一项功能或逻辑应只在一个地方实现一次，而不应在多个位置重复出现。

不要重复你自己（Don’t Repeat Yourself，简称 DRY）是指在软件系统中，每一项知识或逻辑应在系统中有且只有一个明确、一致的表示。

需要注意的是，DRY 的核心是避免逻辑上的重复，而不是机械地消除所有形式上的重复。

代码复用不仅是减少重复代码，更是通过合理的抽象与组织，使代码更易维护、扩展和理解。

函数

Section titled “函数”

函数 是最基础的代码组织和复用方式之一，它可以将一段逻辑封装起来，在需要时重复调用。

Note

函数（Function）：函数是将一段可复用的逻辑封装起来的代码单元，它可以接收输入（参数），并返回结果。

我们最早接触的是数学中的函数概念，例如：y=2x−1y=2x-1y=2x−1 也可以写成 f(x)=2x−1f(x)=2x-1f(x)=2x−1，xxx 是自变量，yyy(或 f(x)f(x)f(x)) 是因变量。当我们定义了这个函数后，表达式 a=3×(2x−1)a=3 \times (2x-1)a=3×(2x−1) 可以写成 a=3f(x)a=3f(x)a=3f(x)。

在编程中也是类似的，我们可以把一段需要重复执行的逻辑封装到函数中。函数可以接收输入（参数），并返回结果。在需要使用该逻辑时，只需调用函数即可。

例如：

  • Python
  • C
  • TypeScript

类

Section titled “类”

在数学中，我们通常只关注“计算过程”，例如函数 f(x)=2x−1f(x)=2x-1f(x)=2x−1，输入一个值就可以得到结果。但在现实问题中，我们往往需要描述一个 “对象”，例如一只狗，它不仅有数据（名字、年龄），还有行为（吃东西、叫）。

Note

对象（Object）：对象是类的一个具体实例，表示现实世界中的一个具体事物，它包含数据（属性）和行为（方法）。

这类“数据 + 行为”的组合，如果只用函数来表示，这些数据和行为通常会分散在不同函数中，难以表达“数据与行为之间的关联关系”，也不利于建模现实世界中的对象，而 类 可以把它们组织在一起。

Note

类（Class）：类是对一类具有相同属性和行为的对象的抽象描述，它定义了对象的结构和行为。

在编程中，类用于描述一类对象。类中可以定义：

  • 属性：用于保存对象的状态（如名字、年龄）
  • 方法：用于定义对象的行为（如吃东西）

Note

属性（Attribute）：用于描述对象状态的数据，是对象所具有的特征或信息。

方法（Method）：定义在类中的函数，用于描述对象的行为。

我们可以根据类创建具体的对象，然后通过对象来访问它的属性和方法。

例如：

  • Python
  • C
  • TypeScript

C 语言没有类的概念，通常使用 struct 和函数来模拟“对象”和“方法”的效果。

模块

Section titled “模块”

函数和类主要用于实现代码复用，但在实际开发中，还需要进一步考虑如何对这些函数和类进行组织和管理。

通常使用 模块 来解决代码组织问题。在多数编程语言中，一个文件通常对应一个模块，可以将功能相近的函数或类放在同一个模块中。

Note

模块（Module）：将相关代码（如函数、类等）组织在一起的基本单位，通常以一个文件的形式存在。

模块不仅仅是将代码按功能拆分到不同文件中，还提供了 命名空间 隔离的作用。

Note

命名空间（Namespace）：用于组织和区分标识符（如变量、函数、类等）名称的作用域，以避免命名冲突。

不同模块中的函数或类可以使用相同的名称而不会发生冲突。如果缺乏模块划分，大量代码可能集中在同一全局作用域中，从而导致命名冲突或被覆盖的问题。

模块是组织代码的基本单位，它通过对功能进行分组，并提供命名空间隔离，使代码结构更加清晰且易于维护。

  • Python
  • C
  • TypeScript
  • dog.py
  • main.py
  • math_utils.py
  • dog.h
  • dog.c
  • math_utils.h
  • math_utils.c
  • main.c
  • math_utils.ts
  • dog.ts
  • main.ts

包

Section titled “包”

当模块数量增多时，仅靠文件难以管理。通常可以根据功能将模块放入不同的目录中进行组织，这种由多个模块组成的 目录 结构称为 包。

Note

目录（Directory）：用于组织和管理文件及子目录的结构单位，是文件系统中的基本层级组织方式。

包（Package）：由多个相关模块组成的代码组织单位，通常以目录的形式存在，用于对模块进行更高层次的管理。

模块是单个文件级别的代码组织单位，而包是由多个模块组成的目录结构，用于更高层次的代码组织。一个包通常是一个目录，其中包含多个模块文件，甚至可以包含 子包（嵌套目录）。

Note

子包（Subpackage）：包含在包内部的包，是包的层级化组织形式，用于进一步细分和组织代码结构。

包不仅可以在项目内部组织和复用代码，还可以作为分发单位在不同项目之间共享。包可以通过特定机制对外暴露统一接口，隐藏内部实现细节。

大多数编程语言都提供 包管理工具（如 pip、npm），通过这些工具可以方便地安装和使用他人发布的代码包，从而避免重复开发。

Note

包管理工具（Package Manager）：用于安装、更新、删除和管理代码包及其依赖关系的软件工具。

此外，包还提供命名空间隔离，不同包中的模块可以使用相同名称而不会发生冲突。

包是用于组织和管理多个模块的结构单位，通常以目录的形式存在，并提供命名空间隔离和代码分发能力。

在不同语言中，包的具体形式有所不同，例如：

  • Python：包通常是包含 __init__.py 的目录
  • Node.js：包通常由 package.json 定义

库

Section titled “库”

模块和包是从代码结构上对代码进行层次划分的方式。当一组模块和包被组织起来，并对外提供可复用的功能时，就形成了 库。

Note

库（Library）：由多个模块或包组成的代码集合，对外提供可复用的功能，供其他程序调用。

库的核心在于对外提供 接口（API），使用者可以通过这些接口调用功能，而无需关心其内部实现。通过库，开发者可以复用已有代码，避免重复开发，提高开发效率。

Note

接口（Interface）：系统或模块对外暴露的一组可调用的功能或操作的定义，用于规定如何与其进行交互。

一个成熟的库通常会提供清晰的接口设计、完善的文档，以及良好的 版本管理 机制。

Note

版本管理（Version Management）：对软件或代码在不同阶段的版本进行记录、控制和维护的过程。

许多编程语言在发布时会附带一些常用功能的库，这些库称为 标准库（Standard Library） 或 内置库（Built-in Library）。此外，还有大量由社区或第三方提供的库，可以通过包管理工具进行安装和使用。

Note

标准库（Standard Library，又称 内置库（Built-in Library））：随编程语言一同提供的一组预先实现的常用功能代码库，开发者可以直接使用而无需额外安装。

框架

Section titled “框架”

在使用库时，开发者通常主动调用库中已经实现的函数或类。在实际开发中，许多项目在结构和执行流程上具有共性，可以将这些通用部分抽离出来，形成 框架。

Note

框架（Framework）：为某一类应用提供基础结构和通用功能的代码集合，它规定了程序的组织方式和执行流程，开发者在其基础上编写具体业务逻辑。

在使用框架时，开发者只需编写由框架调用的业务代码。

使用框架可以加快项目开发速度，并通过约定使项目结构更加清晰；但同时也带来了较高的学习成本，并可能降低灵活性。

与库不同，框架通常通过控制反转（Inversion of Control），即由框架调用开发者编写的代码。库更像是工具，由开发者按需调用；而框架则提供了整体结构，开发者需要在其约定的框架内编写代码。

Note

控制反转（Inversion of Control，简称 IoC）：将程序的控制权从开发者代码转移给框架或外部容器，由其负责调用和管理程序执行流程的一种设计思想。

库 vs 框架

对比维度库（Library）框架（Framework）
本质提供功能的代码集合提供结构和流程的代码骨架
控制权开发者控制流程框架控制流程（控制反转）
调用关系开发者调用库框架调用开发者代码
关注点功能实现系统结构与执行流程
使用方式按需引入和调用按照框架约定进行开发
灵活性高相对较低
学习成本较低较高

小结

本节简单介绍了函数、类、模块、包、库和框架等代码复用手段或方式。
