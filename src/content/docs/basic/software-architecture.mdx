了解需求了，就可以开发应用了吗？别急，再等等，我们得理清楚我们要开发的应用的 **软件架构**。

在网络尚未普及之前，大多数应用运行在单台计算机上，彼此之间无法通过网络进行数据交换，这类软件通常采用 **单机架构**；如果要实现应用的数据在不同计算机之间传递，需要物理介质中转。

<Aside type="note">
**单机架构**（**Standalone Architecture**）是指整个系统（应用程序、业务逻辑、数据库等）全部运行在同一台计算机上的架构模式。
</Aside>

<Aside type="note" title="思考">
为什么不同计算机的数据要进行传递？
</Aside>

当 **网络** 发明后，计算机之间可以通过 **网络协议** 来实现数据传输，简单高效。即便有了网络，由于种种限制，在任意两台计算机之间进行数据传递仍是困难的，人们构思出了一种 **客户端 - 服务器架构（Client-Server Architecture）**。

<Aside type="note">
**网络**（**Network**）是指：将多个计算机或设备通过通信线路连接起来，实现数据交换和资源共享的系统。

**网络协议**（**Network Protocol**）是指为了实现计算机之间在网络中的通信而制定的一系列规则、标准和约定。

**客户端 - 服务器架构**（**Client–Server Architecture**）是指将系统划分为客户端（Client）和服务器（Server）两部分，由客户端发出请求，服务器接收请求并提供资源或服务的一种网络架构模式。
</Aside>

<Aside type="note" title="思考">
为什么说 **“即便有了网络，由于种种限制，在任意两台计算机之间进行数据传递是困难的”**?
</Aside>

在这种架构下，如果两台计算机的某一应用要进行数据传递，只需要将数据先传递到第三台计算机，然后再将数据下载到各自的计算机就可以了，这个“第三台计算机”被称为 **服务器（Server）**；另外两台计算机被称为 **客户端（Client）**；将数据从客户端传递到服务器的过程被称为 **上传**，我们在为我们的应用设置头像时，通常会在相册或文件夹选择并发送一张图片，这个过程就是“上传”，更常见的，我们在微信给朋友发送一条消息，也是将我们的聊天数据上传到微信的服务器；将数据从服务器传递到客户端的过程被称为 **下载**，提到“下载”更多人反应是在网络上下载图片、音频、视频，其实我们也是通过“下载”收到朋友的消息的。

<Aside type="note">
**服务器**（**Server**）是指在网络环境中，为其他计算机（客户端）提供资源、数据或服务的计算机或程序。

**客户端**（**Client**）是指在网络环境中，向服务器发出请求并接收服务或数据的计算机或程序。

**上传**（**Upload**）是指将数据从本地设备（客户端）传输到远程服务器的过程。

**下载**（**Download**）是将数据从远程服务器通过网络传输到本地设备（客户端）的过程。
</Aside>

计算机的处理能力受限于软硬件条件，当一台服务器无法处理客户端发送任务时，最通用的办法会新增新的服务器，这样两台及以上的服务器就组成了一个 **服务器集群**。春晚曾经做过抢红包的活动，有几亿用户同时抢红包，一台服务器是远远不足够处理这些任务的，需要几百台服务器组成服务器集群才能支撑活动。

<Aside type="note">
**服务器集群**（**Cluster**）指多台服务器协同工作，对外提供同一服务的系统结构。
</Aside>

单机架构和客户端 - 服务器架构等，都属于对软件系统整体结构进行设计与规划的方式，我们将这种整体结构设计称为**软件架构**。

<Aside type="note">
**软件架构**（**Software Architecture**）：对软件系统的整体结构进行设计与规划，包括系统的组成部分、各部分的职责划分以及它们之间的关系和交互方式。
</Aside>

软件架构不仅包括单机架构和客户端 - 服务器架构，还包括分层架构、微服务架构、分布式架构等多种形式。在实际开发中，许多应用在初期阶段往往可以采用单机架构或客户端 - 服务器架构来满足基本需求。

<Aside type="tip" title="小结">
本节介绍了两种基础的应用架构——单机架构和客户端 - 服务器架构。

**“单机架构”与“客户端 - 服务器架构”简单对比**

| 维度 | 单机架构 | 客户端 - 服务器架构 |
| :--- | :--- | :--- |
| 网络依赖 | 无 (核心功能离线可用) | 强依赖 (断网即不可用或功能受限) |
| 数据存储 | 数据本地存储 | 服务器数据集中存储 |
| 用户 | 仅供本机用户使用 | 多用户 |
| 扩展性 | 差 | 好 |
| 安全性 | 低 (数据在本地，易被篡改/窃取) | 高 (核心逻辑和数据在服务器，可控) |
| 开发复杂度 | 低 | 高 |
| 典型应用 | 单机游戏 | 微信，网站系统 |
